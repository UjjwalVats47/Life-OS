PROJECT IDENTITY

Project Name

The System: Life OS

Core Idea

A comprehensive personal life management operating system inspired by the Solo Leveling anime/webtoon. It combines behavioral psychology, gamification, goal hierarchy, task scheduling, and AI-driven coaching to help users systematically improve their lives through structured goal progression, habit tracking, and quantified self-improvement.

Main Problem It Solves

•Goal fragmentation: Users have multiple competing goals (academic, fitness, financial, personal) without a unified system to prioritize and track them

•Habit chaos: Lack of structured approach to building good habits and eliminating bad ones

•Motivation deficit: No gamified feedback loop to maintain motivation during long-term goal pursuit

•Behavioral blindness: Users don't understand their own productivity patterns, mood correlations, or what actually works for them

•Willpower depletion: No intelligent system to help users make better decisions about goal trade-offs and override requests

Target Users

•Primary: Ambitious individuals (students, professionals, entrepreneurs) aged 18-40 who want systematic self-improvement

•Secondary: People struggling with habit formation, goal management, or motivation

•Tertiary: Users interested in gamification, behavioral psychology, or Solo Leveling anime aesthetic

Why This Project Was Created

User (Ujjwal Vats) wanted to build a personal life management system that combines:



Dual goal hierarchy (sys1: time-based hierarchical; sys2: importance-based dynamic)



Solo Leveling anime aesthetic and terminology (ranks, XP, "awakening," "hunter's log")



Behavioral analytics to understand personal productivity patterns



AI-driven reasoning to prevent goal override abuse



Gamification with badges, rank progression, and stat tracking

Expected Final Outcome

A fully functional web application where users can:

•Complete onboarding ("The Awakening") to set up their life system

•Define primary/secondary goals with time horizons

•Receive daily task recommendations based on goal hierarchy and scheduling algorithm

•Complete tasks and earn XP, which progresses their rank

•View analytics ("Hunter's Log") showing productivity patterns and AI insights

•Interact with an AI chatbot for goal reasoning and motivation

•Track habits, streaks, and behavioral patterns

•Unlock achievements and badges as they progress

What Makes It Different/Valuable



Dual goal system: Combines time-based hierarchy (sys1) with importance-based dynamics (sys2), not just a flat task list



Scheduling intelligence: "Two best-suited options" per time slot with escalation phases (Early/Mid/Late) as deadlines approach



Behavioral analytics: Analyzes mood, stress, time-of-day performance, and habit correlations with AI commentary



Override reasoning gate: AI validates goal override requests against hierarchy and reasoning, with penalties



Solo Leveling aesthetic: Gamification with anime-inspired ranks, XP, status windows, and terminology



Passive habit redirection: Gradually reduces bad habits while suggesting healthy replacements

COMPLETE PROJECT UNDERSTANDING

System Overview

The System: Life OS is a full-stack web application that manages a user's life through a structured hierarchy of goals, habits, and daily tasks, all wrapped in a gamification layer inspired by Solo Leveling.

User Journey (Intended Flow)



Authentication: User logs in via Manus OAuth. If onboardingCompleted=false, they are forced to "The Awakening" wizard.



The Awakening (Onboarding):

•Step 1: Welcome screen explaining the system

•Step 2: Define weekly schedule (fixed slots like work/school/sleep, flexible slots for tasks)

•Step 3: Set 1-2 primary goals (6-12 month horizon)

•Step 4: Set 2-3 secondary goals (2-3 month horizon)

•Step 5: Input personality type (16Personalities)

•Step 6: Select financial status

•Step 7: List target habits to eliminate

•Step 8: Review and confirm

•Backend action: Creates weekly schedule rows, sys1 goals, target habits, initializes user_stats and user_settings, marks onboardingCompleted=true





Main Dashboard:

•Displays user rank, XP, current level, and stat breakdown

•Shows daily tasks for today grouped by time slot

•Displays primary goal progress

•Renders notification center and AI chatbot





Task Completion Flow:

•User sees task in dashboard

•Clicks task → TaskConfirmationDialog opens

•User confirms completion

•Backend: Awards XP, updates rank/level, checks for level-up, triggers badge unlock checks

•Frontend: Shows level-up animation if rank increased, shows badge notification if unlocked

•Dashboard refreshes to show new stats





Analytics ("Hunter's Log"):

•Shows XP trends, time-of-day performance, day-of-week patterns

•Displays goal progress multi-line charts

•Shows mood/stress trends and correlations

•Provides AI-generated commentary on productivity patterns





AI Chatbot:

•Responds to user queries with one of three tones: Cold Architect (logical, firm), Strategic Mentor (encouraging, disciplined), Shadow Guard (supportive, rare)

•Tone selection based on context (stress level, mood, addiction triggers)

•Currently returns simulated responses; not yet wired to real LLM



Core Concepts

System 1 Goals (Hierarchical, Time-Based)

•Primary: 1-2 goals, 6-12 month horizon, highest priority weight (10)

•Secondary: 2-3 goals, 2-3 month horizon, medium priority weight (5)

•Tertiary: Future expansion, lower priority weight (2)

•Override Protection: Overriding a primary goal costs significant XP and requires AI reasoning validation

System 2 Goals (Importance-Based, Dynamic)

•Critical: Must-do goals, managed by AI

•Negotiable: Can be adjusted based on behavior

•Optional: Lower priority, can be dropped

•Purpose: Allows AI to dynamically adjust goals based on user performance and context

Task Scheduling Algorithm (Weekly Slot Allocation)

•User defines fixed slots (work, school, sleep) and flexible slots (study, exercise, etc.)

•System allocates tasks to flexible slots, offering "two best-suited options" per slot

•Phase 1 (Early): Offer tasks as options; user can skip

•Phase 2 (Mid): Escalate priority as deadline approaches

•Phase 3 (Late/Mandatory): Force fixed slots for incomplete tasks

•Postponement tracking: Each postponement increments escalation phase

Gamification System

•XP: Earned by completing tasks (base: 100 for primary, 50 for secondary, 25 for tertiary + streak bonuses)

•Ranks: E → D → C → B → A → Elite → Knight → Commander → S → General → Monarch

•Stats: Intelligence, Vitality, Focus, Discipline, Sense (increase based on habit completion category)

•Streaks: Current, longest, average (break detection at 2+ days)

•Badges: 21 badge definitions tied to rank milestones, streak achievements, and special conditions

•Levels: Calculated from total XP; each level requires progressively more XP

Behavioral Analytics

•Tracks mood, stress, time-of-day performance, day-of-week patterns

•Correlates mood with task completion, spending, and other factors

•Generates AI commentary on productivity rhythms

•Identifies "why did mood drop" patterns

ALL DECISIONS AND REASONING

Decision 1: Dual Goal System (sys1 + sys2)

•Final decision: Implement two separate goal systems

•sys1: Hierarchical (primary > secondary > tertiary) with time horizons

•sys2: Importance-based (critical > negotiable > optional) with dynamic AI adjustment



•Why chosen:

•sys1 provides user-defined structure and override protection

•sys2 allows AI flexibility without violating user's core commitments

•Combination prevents both goal chaos and rigid inflexibility



•Alternatives considered:

•Single flat goal list: Too simple, no hierarchy for override protection

•Only hierarchical: Too rigid, no flexibility for AI adjustment

•Only importance-based: No user control, all AI-driven



•Trade-offs:

•More complex to implement and explain to users

•More database tables and queries

•Richer goal management possible



•Final or changeable: Final; core to system design

Decision 2: Solo Leveling Aesthetic

•Final decision: Use Solo Leveling anime terminology and visual style

•Ranks (E → Monarch)

•XP and leveling

•"The Awakening" onboarding

•"Hunter's Log" analytics

•Status window UI

•Why chosen:

•Provides thematic coherence and motivation

•Anime aesthetic appeals to target demographic

•Gamification feels natural in this context

•Alternatives considered:

•Generic gamification (badges, points, leaderboards): Less thematic

•Other anime (My Hero Academia, Demon Slayer): Less fitting for life OS

•No aesthetic theme: Less engaging

•Trade-offs:

•Narrows appeal to anime fans

•Requires consistent visual design

•May feel gimmicky to some users

•Final or changeable: Final; core brand identity

Decision 3: Task Scheduling Algorithm

•Final decision:

•Allocate tasks to weekly schedule slots

•Offer "two best-suited options" per flexible slot

•Three escalation phases (Early/Mid/Late) as deadline approaches

•Postponement tracking increases escalation phase

•Why chosen:

•Gives users choice without overwhelming them

•Escalation phases prevent procrastination

•Respects user's fixed schedule

•Alternatives considered:

•Random task assignment: Users feel no control

•All tasks at once: Overwhelming

•Strict scheduling: Too rigid

•Single task per slot: Too restrictive

•Trade-offs:

•More complex algorithm

•Requires good task prioritization logic

•May feel pushy if escalation phases too aggressive

•Final or changeable: Changeable; can adjust escalation phases based on user feedback

•Known bug: Escalation phase currently calculated from postponement count instead of days-until-deadline

Decision 4: Gamification System

•Final decision:

•XP earned from task completion (base varies by goal level + streak bonus)

•11-rank progression (E → Monarch) with exponential XP requirements

•5 stats (Intelligence, Vitality, Focus, Discipline, Sense)

•Streak tracking with 2-day break detection

•21+ badges for milestones and special achievements

•Why chosen:

•Provides multiple feedback loops (XP, ranks, stats, streaks, badges)

•Exponential XP requirements maintain long-term engagement

•5 stats allow category-specific progression

•Streaks encourage consistency

•Badges provide recognition for specific accomplishments

•Alternatives considered:

•Simple points system: Less engaging

•Only badges: No progression feeling

•Only ranks: No stat variety

•Trade-offs:

•More complex to implement and balance

•More database queries

•Risk of grinding mentality if not balanced well

•Final or changeable: Changeable; XP values and thresholds can be tuned based on user feedback

Decision 5: Onboarding Wizard (8 Steps)

•Final decision:

•8-step wizard ("The Awakening")

•Steps: Welcome, Schedule, Primary Goals, Secondary Goals, Personality, Financial, Target Habits, Review

•Primary goals and secondary goals required; target habits optional

•Redirect to dashboard on completion


•Why chosen:

•8 steps balance thoroughness with friction

•Optional target habits reduce friction for users not ready

•Review step prevents accidental misconfiguration


•Alternatives considered:

•10+ steps: Too long, high abandonment

•3-5 steps: Too little information, poor system setup

•All optional: Users skip important setup

•All required: High friction


•Trade-offs:

•8 steps still takes 5-10 minutes

•Some users may abandon mid-wizard

•Optional steps may be skipped by users who need them

•Final or changeable: Changeable; can add/remove steps based on user feedback
